# 一键贡献 (contribute-pr)

Hanflow 提供了一个 AI 辅助贡献技能 **contribute-pr**,让你无需熟悉全部代码,也能在遵循
Hanflow 架构规约的前提下,完成"选题 → 设计 → 实现 → 提 PR"全流程。

它复用了 Hanflow 自进化体系(loop-evolve)的 scan→code→verify 流程,产出符合 CHARTER 设计
不变量的代码,并以 Pull Request 形式提交——你不需要 `xpc1024/hanflow` 的写权限。

## 它适合谁

- 想贡献但不知道从哪下手的新成员
- 有想法但没时间深挖代码细节的伙伴
- 修复 issue 或补全功能模块的贡献者
- 只想改文档(修错别字、补示例)的贡献者(用 `/contribute-pr docs`)

## 前置准备

1. 安装 ZCode / Claude Code / Codex(三选一)
2. 一键安装 contribute-pr skill(含 loop-evolve 委托依赖 + GitHub CLI 自动安装):

   ```bash
   curl -fsSL https://raw.githubusercontent.com/xpc1024/hanflow-evolve/main/install.sh | bash
   ```

   或手动安装(想审查脚本内容):

   ```bash
   git clone https://github.com/xpc1024/hanflow-evolve
   cd hanflow-evolve && bash install.sh
   ```

   install.sh 会自动完成:
   - clone hanflow-evolve(skill 源) + hanflow(你的 fork) + hanflow-home
   - 安装 contribute-pr + loop-evolve skill 到 `~/.zcode/skills/`
   - 自动 fork hanflow 到你的 GitHub 账号(gh 登录时)或询问你的用户名
   - 配置 upstream remote(发 PR 到 xpc1024/hanflow 需要)
   - **自动安装并引导 GitHub CLI 登录**(见下方"凭证安全")

3. install.sh 会引导 `gh auth login`(浏览器授权),完成后即可触发 skill。

## ⚠️ 凭证安全(请先阅读)

install.sh 和 contribute-pr 在发 PR 时需要 GitHub 凭证。**默认走 `gh auth login --web`**:
你只需在浏览器点 Authorize,凭证由 gh 安全存储在本机系统 credential store
(Windows Credential Manager / macOS Keychain),**Hanflow 不接触你的凭证**。

- 全程**不需要**你的 GitHub 账号密码
- 凭证由 gh 官方管理,随时可 `gh auth logout` 一键撤销
- 无浏览器环境(服务器)或不愿用 gh auth 时,可改用 fine-grained PAT 路径(零持久化),
  详见 skill 的 `references/credential-handling.md`

## 完整流程

```
1. scan              采集信号 (issues/stubs/learnings)
2. prioritize        打分排序候选主题
3. check_occupied    去重 (查 GitHub PR + 本机档案, 避免撞主题)
4. human_topic       (可选) 你直接指定主题, 跳过 1-3
5. plan              生成方向计划
6. audit_direction   AUDIT 方向
7. gate1             等待你确认方向
8. design            概要 + 架构设计
9. audit_design      AUDIT 设计
10. gate2            等待你确认设计
11. plan_exec        生成执行计划
12. code             TDD 实现 (在 evolve/<contribution_id> 分支)
13. verify           测试 + smoke + auto-fix
14. gate3            等待你最终确认
15. submit           S0 质量门 + fork push + 发 PR (代码 + 可选文档)
```

## 质量保证(为什么维护者可以侧重评估需求价值)

submit 前会跑 **S0 质量门**(本地就绪检查):
- charter-check 架构守护复核(CHARTER 设计不变量)
- ruff lint 零告警
- conventional commits 提交规范

发出的 PR 描述会**附真实数据**(测试通过数、守护项、lint 状态),让维护者一眼看到质量已验证。

**诚实说明**:本地 S0 全绿 ≠ GitHub CI 必绿(环境差异),维护者大概率只需评估需求价值,
但仍可能遇到 CI 环境差异需你适配——这是 skill 无法完全消除的残留工作。

## 防重复机制

选题阶段的 `check_occupied` 会查询上游 GitHub PR(xpc1024/hanflow + hanflow-home)和本机
CONTRIBUTIONS.md,避免你与他人或历史贡献撞主题:
- 活跃 PR(open)→ 硬 skip,不能选
- 已合并的 PR(merged)→ 提示"此功能已于 X 由 @y 合并,可做增强版"
- 已关闭的 PR(closed)→ 提示"曾被提交但未合并,查看原因后再决定"

## 命令一览

| 命令 | 行为 |
|------|------|
| `/contribute-pr` | 从当前阶段继续,或开始新贡献 |
| `/contribute-pr topic <描述>` | 你直接指定主题,跳过选题 |
| `/contribute-pr docs <描述>` | 纯文档贡献,跳到 hanflow-home |
| `/contribute-pr status` | 打印当前状态 + 本机贡献档案 |
| `/contribute-pr refresh` | 刷新本机贡献档案状态(gh pr view) |
| `/contribute-pr gate approve\|revise\|reject` | Gate 阶段确认 |
| `/contribute-pr abort` | 终止当前贡献,清理凭证 |

## FAQ

**Q: 我的 GitHub 凭证会被 Hanflow 收集吗?**
A: 不会。默认走 gh auth,凭证由 gh 官方存储,Hanflow 不接触。详见"凭证安全"。

**Q: 我只想改文档(错别字、示例)怎么办?**
A: 用 `/contribute-pr docs <描述>`,跳过代码阶段,直接在 hanflow-home 走提交流程。

**Q: 我和别人的 PR 撞主题了?**
A: `check_occupied` 会提前提示。若都已发出,GitHub 的 PR-create-fail 会兜底(分支已有 PR
时 skill 幂等取已存在 URL,不产生重复 PR)。

**Q: 跨机器能同步我的贡献历史吗?**
A: 本机 CONTRIBUTIONS.md 是单机档案,跨机器不同步。但跨贡献者去重靠 GitHub PR 查询(全局
真相源),不依赖你的本地档案。

Codex 没有原生 skill 机制。把下面片段粘贴到项目根的 `AGENTS.md`,即可在对话里触发:

```markdown
<!-- AGENTS.md 片段(Codex 用户粘贴) -->
## Hanflow 社区贡献 skill (contribute-pr)

当用户说"给 hanflow 提 PR""社区贡献""contribute-pr"时,按以下流程执行:

1. 读取 ~/.zcode/skills/contribute-pr/SKILL.md(若不存在,提示用户运行
   curl -fsSL https://raw.githubusercontent.com/xpc1024/hanflow-evolve/main/install.sh | bash)
2. 按 SKILL.md 的阶段路由执行,工具映射:
   - "调用 Agent/子 agent" → 用 Task 工具
   - "Edit/Write 文件"    → 用 apply_patch
   - 其余 Bash/Read 与 Codex 原生一致
3. 凭证安全声明必须先打印(见 credential-handling.md)
```
