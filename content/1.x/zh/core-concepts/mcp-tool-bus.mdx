# MCP 工具总线

总线解析 `server.tool` 名，路由到连接，按 input schema 校验参数，施加每服务限流，
开启 trace span，然后调用。失败时重试，除非工具标注为 `destructive`。

## 传输

远程传输经官方 `mcp` SDK 说 MCP 协议（v1.3.0 起，ADR-0008）。总线在 `start()`
时连接非 lazy 服务；单个服务失败会被隔离（告警但不阻断总线），`lazy: true`
的服务在首次使用时连接。

| 传输 | 用途 |
| --- | --- |
| `stdio` | 本地 MCP server 子进程（生产可用） |
| `http` | MCP **Streamable HTTP** —— 生产远程主路径 |
| `sse` | 旧式 HTTP+SSE 桥接（MCP 规范已弃用，连接时告警） |
| `websocket` | **占位** —— MCP 协议未定义 websocket 传输，`connect()` 抛 `NotImplementedError` |
| `inprocess` | 内置服务，无网络 |

远程失败包装为稳定错误码：服务配置无效抛 `MCP_CONFIG_INVALID`，连接/握手/IO
失败抛 `MCP_CONN_FAILED`（可重试），远端工具自身报错抛 `TOOL_EXEC_FAILED`。

## 内置服务

Hanflow 自带七个内置 MCP 服务：`code_exec`、`filesystem`、`http_request`、
`shell`、`vector_search`、`web_fetch`、`web_search`。默认配置把 `web_search`
装配为进程内。

```yaml
mcp_servers:
  web_search: { transport: inprocess }
  filesystem:
    transport: stdio
    command: node
    args: ["./mcp/fs-server.js"]
```

## 调用工具

```yaml
- id: search
  type: Tool
  config:
    tool: web_search.search
    args: { query: "{{input.q}}" }
```

工具名必须为 `server.tool` 形式。破坏性工具不重试。
